# 레비 스트리밍·일시 요약·운영 지표

## 대화 흐름

`POST /ephemeral/respond`는 `Accept: text/event-stream`이면 SSE로 응답하고, 기존 JSON 요청도 유지합니다. 요청에는 최근 `messages`와 선택적인 `summary`를 보냅니다. 본문은 생성되는 대로 `delta`로 전달하고, 완성된 본문 `reply`를 선택지 생성 전에 보냅니다. 그 뒤 `options`, `done`을 전송합니다. HTTP 헤더를 보낸 뒤 생긴 오류는 원문 없이 `error`와 허용된 코드만 전송합니다.

이전 대화가 12메시지 이상이거나 요약을 포함한 문맥이 8,000자를 넘으면 서버가 오래된 부분을 요약합니다. 최근 5메시지는 그대로 두고, 갱신한 요약과 유지할 메시지 수를 `context`로 전달합니다. 브라우저는 응답이 완료됐을 때만 갱신한 문맥을 채택합니다. 요약이나 답변이 실패하면 이전 문맥과 입력을 유지하며 자동 유료 재시도는 하지 않습니다.

화면의 전체 대화와 다음 요청에 사용할 요약·최근 문맥은 브라우저 RAM에만 둡니다. 서버에는 요청 처리 중에만 존재하며 DB·localStorage·sessionStorage·IndexedDB·URL에 넣지 않습니다. 종료·새로고침·페이지 이동·BFCache 복원·계정 변경 시 제거합니다. API 제공자는 원문과 요약을 처리하며 제공자 보관은 별도 정책의 적용을 받습니다. 모델 호출의 `store: false`는 유지합니다.

공개 채팅의 키워드 위기 판정과 고정 안내 UI는 제거했습니다. 이전 저장형 채팅은 계속 운영에서 차단됩니다. 모델 프롬프트의 의료 판단·위험 행동·관계 의존 관련 기본 경계는 유지합니다.

## 오류 문구

문구는 사용자 확인 후 `apps/web/src/lib/chat-errors.ts`에 모았습니다. 네트워크, 시간 초과, 이용량 한도, 장애, 중간 끊김, 요약 실패, 동시 요청, 인증 만료, 입력 오류를 구분합니다. 원격 서버의 임의 메시지·예외 본문을 화면에 표시하지 않습니다. 전송 실패 시 마지막 입력을 돌려주고 미완성 응답은 다음 문맥에 넣지 않습니다. 인증 만료 시 원문을 지우고 로그인하거나, 기존 토큰을 지우고 비로그인 새 대화를 시작할 수 있습니다.

생성·요약·선택지는 서버에서 전체 30초 제한을 공유합니다. 선택지 생성이 실패하거나 제한 시간이 끝나도 이미 완성된 본문은 기본 선택지와 반환합니다. 브라우저에는 연결이 멈춘 경우를 위한 40초 제한이 별도로 있습니다. 종료·페이지 이동은 서버 모델 호출까지 취소 신호를 전달합니다.

## Sentry 연결

서버 집계 지표만 수집합니다. 브라우저 Sentry·Replay·trace·profile·로그·오류 이벤트 전송은 계속 비활성화합니다. 현재 작업 환경에는 DSN이 없으며 실제 Sentry 계정·배포 설정·대시보드 수신은 확인하지 못했습니다.

API 배포 서비스의 환경변수에 설정하고 API를 재배포하세요. DSN은 소스나 채팅에 붙여넣지 말고 배포 환경의 변수로 관리합니다.

```dotenv
SENTRY_DSN=<서버 프로젝트의 DSN>
SENTRY_METRICS_ENABLED=true
```

환경변수가 없으면 전송하지 않습니다. 별도 서버 프로젝트를 사용하면 기존 프런트 프로젝트와 요청 통계를 구분하기 쉽습니다. 현재 프런트 빌드 설정에 지정된 조직·프로젝트가 서버 지표 수신 프로젝트라는 뜻은 아닙니다.

| 지표                    | 의미                                                             | 분류                                                           |
| ----------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------- |
| `levi.chat.requests`    | 컨트롤러에 도달한 요청 수                                        | `outcome`                                                      |
| `levi.chat.duration`    | 요청부터 완료·실패·취소까지 서버 시간(ms)                        | `outcome`                                                      |
| `levi.chat.first_token` | SSE 요청 시작부터 첫 본문 청크까지 서버 시간(ms), 요약 시간 포함 | 없음                                                           |
| `levi.chat.rejected`    | 인증·입력·분당 제한 등 컨트롤러 이전에 거절된 요청 수            | `outcome`                                                      |
| `levi.chat.summaries`   | 완료된 문맥 요약 수                                              | 없음                                                           |
| `levi.ai.tokens`        | 제공자가 반환한 실제 입력·출력 토큰 합계                         | `operation`: reply/options/summary, `token_type`: input/output |

Sentry Metrics에서 위 이름으로 검색해 요청 수를 결과별로 묶고, 처리 시간과 첫 청크 시간의 p50·p95를 확인합니다. 취소는 실패와 따로 표시합니다. 컨트롤러 이전 거절은 `rejected`에서 별도로 확인합니다. 입력·출력 토큰을 작업별로 합산하면 사용량을 확인할 수 있지만 실제 청구액은 제공자 요금·캐시·실패 처리에 따라 달라집니다. 중간 취소처럼 제공자 usage가 도착하지 않은 호출은 토큰 합계에 반영되지 않을 수 있습니다.

## 개인정보 전송 경계

- 지표 이름·숫자·단위와 고정된 결과/작업/토큰 종류만 허용합니다. 상담 원문·요약·캐릭터 이름·ID·IP·이메일·URL·오류 본문·stack은 수집하지 않습니다.
- `beforeSendMetric`에서 허용 목록으로 재구성합니다. 설치된 SDK가 그 뒤 scope 속성을 다시 합치는 동작도 확인했으므로, 실제 전송 직전 transport에서 한 번 더 허용 목록으로 재구성합니다.
- transport는 metric 이외의 envelope를 모두 버리고, 원래 trace/span 식별자도 전달하지 않습니다. 지표용 임의 식별자는 개별 지표마다 새로 만듭니다.
- 예외·transaction·breadcrumb·로그 후크는 모두 내용을 버립니다. 전체 SDK 자동 수집을 켜는 방식이 아닙니다.
- 이 설정은 애플리케이션 SDK 범위입니다. 호스팅·프록시·AI 제공자의 보관 및 접근 로그 정책은 별도로 확인해야 합니다.

## 배포 후 확인

1. API에 유효한 모델 키와 `TO_HIGH_LLM_DAILY_REQUEST_LIMIT`가 있는지 확인합니다. 비밀값은 출력하지 않습니다.
2. 합성 문장으로 첫 본문이 선택지보다 먼저 표시되는지 확인합니다. 실제 모델 품질·속도는 모의 테스트 결과로 대체하지 않습니다.
3. 10왕복 이후에도 대화가 이어지고 종료·새로고침 후 요약이 다음 요청에 붙지 않는지 확인합니다.
4. Sentry 프로젝트에서 위 지표를 검색하고 실제 수신·요금제의 Metrics 지원 여부를 확인합니다. 원문이나 요약을 지표 태그로 추가하지 않습니다.
5. Sentry 연결 장애는 상담 응답을 막는 조건으로 삼지 않습니다. 일일 제한은 현재 프로세스 RAM 카운터이므로 전역 비용 상한을 보장하는 기능과는 별개입니다.
